# Support

## Where to ask

- Use a GitHub issue with the bug-report template for reproducible defects.
- Use the feature-request template for enhancements or research proposals.
- Use a focused issue for installation or usage questions that are not answered
  by the README or existing issues.

Before opening an issue, search the documentation and existing open and closed
issues.

## Information to include

Provide the smallest reproducible example possible, including:

- operating system;
- Python and Node.js versions;
- installation method;
- exact command or workflow;
- expected and actual behaviour;
- relevant logs or traceback with secrets removed; and
- whether the data are synthetic, replayed, or live.

## Support boundary

Support is provided on a best-effort basis. There is no guaranteed response or
resolution time. The project is research software and is not investment advice,
a trading recommendation, an execution service, or a production brokerage
integration.

Only the latest release and the current `main` branch are actively considered
for support. Questions about private forks or substantial custom deployments
may require independent investigation.

## Sensitive reports

Do not disclose vulnerabilities, credentials, personal information, or
proprietary data in a public issue. Follow [SECURITY.md](SECURITY.md) instead.
